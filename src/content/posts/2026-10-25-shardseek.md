这两天把一个叫 **ShardSeek（愿景显影器）** 的东西从"骨架"推到了能上真机。写这篇不是为了展示，是因为它的想法和我以前做的东西**方向相反**，值得说清楚。

## 一、最核心的想法：它不能生成任何东西

我以前的工具基本是同一个句式：你给一点输入，它给你一个"更好的你"——更好的简历、更好的计划、更好的人设。这类工具的问题不在于不准，而在于**它替你完成了一次判断**，而且完成得很顺滑，顺滑到你不会去反驳。

ShardSeek 是我对这件事的反向操作，核心只有三条：

**1）显影，而非生成。** 用户用 1–2 分钟的短场景做几次微选择，系统把"选择 + 现实障碍 + 最小一步"沉淀成一张卡（我们叫它星屑）。卡上的文字**全部是用户自己说过的原话**，一个字都不是模型编的。模型只能提 proposal，且必须带证据；它不许写 identity，不许写 trait，不许打分。

**2）对照，而非鼓励。** 反馈不是"你真棒"或"你可以的"，而是把「你想要的」和「现实里挡着的」放到同一屏。张力本身就是反馈。产品里明确禁止「你是一个……的人」这类人格结论——不是风格偏好，是写进原则里的硬约束（P-02）。

**3）延迟，而非即时。** 当场不评价。要"积累 + 时间"双门都过，那张卡才被提升为可以回看的星屑；在此之前它只是一次未定的记录，随时可以不认。

两条衍生规则，我觉得比上面三条更能说明这个产品是什么：**可中断**（120 秒内随时能走，跳过不扣分）和**可否定**（历史能撤销，修订走版本链，不覆盖写）。一个只会顺着你说的东西，是不敢让你撤销的。

所以如果只能留一句话：**它不是让你看见未来，是让你看见自己重复说过的那几句话。**

## 二、技术栈：先把"不许做什么"写成架构

整个东西是一个 pnpm monorepo，分五层：

```
apps/web ──→ packages/polaris ──→ packages/memory ──→ packages/contracts
    │              │
    │              └──→ packages/llm ───┘
    └──→ packages/engine ─────────────────┘
```

这些箭头不是画着好看的，是 CI 会跑断言的：

- **`contracts` 不依赖任何内部包**，它是唯一的 schema 真相源（JSON Schema）。
- **`engine` / `memory` / `polaris` 不许 import React、DOM、`fetch`、`localStorage`**。它们是纯领域层，必须能在 Node 里跑测试。`apps/web/src` 里现在 `fetch` 的数量是 **0** ——内容在构建期就被编译进 bundle 了。
- **只有 `packages/llm` 可以发网络请求**，其他地方出现模型调用一律算缺陷。
- **只有 `apps/web/src/lib/adapters/` 能碰浏览器存储**，领域层通过端口取数据。

写代码的人最容易在"顺手 import 一下"里把分层破掉，所以这里的规矩都做成了 `tests/contract/layers.test.ts` 的可执行断言，而不是文档里的一句倡议。

前端是 React 19 + Vite，构建产物 431KB（gzip 133KB）。**数据默认全部本地**：IndexedDB，没有默认的服务端数据库，没有第三方分析，导出格式必须包含完整版本链。

## 三、测试：998 个，分三类

`pnpm check` 会一次跑完 typecheck、998 个测试、eslint 和四条内容校验。测试不是凑数的，是按用途分三层的：

| 类型 | 干什么 | 举例 |
|---|---|---|
| 契约测试 | 每个 schema 一条合法样本 + 一条反例 | 星屑卡缺 `supersedes` 必须报错 |
| 回放测试 | 固定事件序列 → 确定的状态与星屑序列，逐字节可复现 | 同一次对话跑两遍，产物哈希必须一致 |
| 原则测试 | 每条产品原则至少一条可执行断言 | 扫全库，出现「你是一个…的人」就红 |

金路径有 4 个场景（五年后 / 留学 / 没回的消息 / 它保护什么），每个都在 95–105 秒的预算内跑通；故事线是「白夜」七幕、六个终幕，连贯性检查 7/7。概念库 36 条（美学 8 / 叙事 8 / 哲学 12 / 心理 8）自检 36/36。

还有一个数字：**33 份 ADR**。每个"我们决定不做什么"都留了档，包括被否决的方案和否决理由。这个后面会救命的。

## 四、然后我真的做了一块板子

网页能证明"流程成立"，证明不了"一张卡在手里是什么感觉"。所以我又把这一张卡做成了固件，烧进一块涂鸦 T5AI 开发板（BK7258，320×480 LCD，8MB PSRAM）。

- **LVGL 9 + C11**，不是把网页塞进 WebView。
- **三张卡一张一屏**，用 LVGL 原生横向滚动 + 居中吸附（`LV_SCROLL_SNAP_CENTER` + `SCROLL_ONE`）——不自己写手势，因为自己写的手势一定会在"快速连划"上崩。
- 触摸是板上那颗 GT1151 电容屏，走 `lv_port_indev` 的 pointer 驱动。
- 每张卡有自己的显影、呼吸、认领状态，但**只有当前卡跑动画**，其余静止——8MB PSRAM 经不起三份动画。
- 编号是两层：顶栏的星轨序号（`No.023` / `No.041` / `No.067`）和右下角的 `2 / 3` 位置。

最费劲的是底纹。视觉上要的是"暗金菱格 + 四角压暗"，金**只作质感，不许发光**、不许当光源。这不能拿一张 PNG 贴上去——屏幕是 320×480，贴图会随卡缩放糊掉。所以写成了纯整数的像素算法：`(x+y)` 与 `(x-y)` 对 pitch 取模落在 0 时混一点金，越靠角落越压暗，全部整数运算，逐像素算 153,600 次。

它被抽成了一个**可以主机编译、不依赖 LVGL 的独立单元**，16 条断言盯着它：格线像素占比必须落在 10%–30%（实测 15.3%）、格线只许比相邻像素亮一点（22 vs 12，亮度差 ≤12，超出就说明金开始发光了）、四角必须比中心暗、整图 FNV-1a 校验和钉死在 `0xAA758FBE`。写完之后我又用 Python 按同一规格重写了一遍算校验和，得到同一个数——这样"是算法对"和"是我 C 写对了"才算分开验证过。

板子的日志现在是这样：

```
==== 星屑匣 · 硬件样机（3 张卡，横向滑动）====
星图 1/3（No.023）：3 点，光球 #0，边 2 条（方框 210px）
星图 2/3（No.041）：4 点，光球 #1，边 3 条（方框 210px）
星图 3/3（No.067）：5 点，光球 #1，边 4 条（方框 210px）
[card] 翻卡容器就绪：3 张，屏宽 320px，横向吸附
[card] 翻到第 2/3 张：No.041
[card] 翻到第 3/3 张：No.067
```

手指横划之后出现的最后两行，是这个项目里我最想看到的日志——它说明"翻卡"不是我在网页里模拟出来的交互，是一个真实的手指动作，在一块真实的屏上，落到了一整屏。

## 五、踩过的坑（这一段才是真实成本）

- **README 骗过人**。项目最早的 README 写着"骨架，没有产品代码，目前还跑不起来"，但仓库里躺着十几张实机截图和一个能用的构建产物。这句话留了两周没人发现，直到有人来问"那截图哪来的"。
- **`file://` 会让 IndexedDB 静默死掉**。我做过一个把所有 JS/CSS 内联的单文件版本（467KB，零外链），`file://` 打开永远是启动页。原因不是 bug：不透明来源拿不到 IndexedDB，而"刷新回到断点"依赖它，代码按原则**拒绝降级**，于是卡住。这个文件最后被我删了——留着只会让人点开一个坏东西，理由写进了 `_FAILED.md`。
- **PowerShell 的一行管道能毁掉整个候选数组**。Windows 侧启动脚本里 `@( (Get-Command py | Select-Object -ExpandProperty Source), … )`，在没有 `py` 的机器上 `Get-Command` 返回 `$null`，喂给 `Select-Object` 抛错，而脚本头部是 `$ErrorActionPreference='Stop'`——整条数组直接变成空集，连写死的路径一起丢。报错长得像"找不到 python"，其实是"我把自己的候选表清空了"。
- **别用带模式串的 `pkill`**。`pkill -f "vite.js preview"` 会匹配到你自己那条 bash 命令行，然后把自己的 shell 杀掉。这件事我犯了两次。

## 六、现在的状态

- 仓库（公开）：https://github.com/RUI-debug769/ShardSeek
- 网页 demo：本地 `pnpm install && pnpm build && pnpm preview`
- 固件：真机烧录成功，2.8MB 整包，三张卡、双向横划、每卡编号，四段会话 21 次翻页日志
- 一页作品介绍：A4 单页，能打印

如果只能用一句话总结我在这个项目里学到的东西：**克制是可以被架构出来的**。不生成、不评价、不给建议——这些事情写成口号一文不值，写成"contracts 不许依赖内部包""P-02 有可执行断言""模型只能写 proposal 且必须带证据"，它才真的会发生。
