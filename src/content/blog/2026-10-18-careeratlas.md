迷茫期问 AI"我该干什么"，多半会得到一堆正确的废话："关键是找到自己热爱的方向。"问题不在模型不聪明，在于**没有流程**：没有标准化输入、没有校准、没有产出约束，AI 只能陪聊，不能施测。

[CareerAtlas](https://github.com/RUI-debug769/careeratlas-app) 把一次真实的"自我测评 → 职业规划"深度流程，沉淀成了可复用的方法资产库：**6 个溯源校验过的题库（共 79 题）+ 标准 SOP + 报告模板 + 外部校准清单 + 一个 Claude Skill**，并在阶段二做成了测评向导 Web 应用。

## 核心思路：用流程约束 AI，而不是让 AI 自由发挥

**AI 是施测员，不是算命先生。** 整个系统的骨架是标准作业流程："探索评估 → 定位决策 → 路径规划"——收集 7 项输入变量，3 轮深度测评（约 50 题，分批施测），挖掘答案间的矛盾，引入外部校准，最后按模板产出《生涯方向分析报告》和行动清单。每一步有完成定义，AI 没有自由发挥的缝隙。

**循证，而不是感觉。** 题库不是拍脑袋攒的：大五人格、霍兰德 RIASEC、舒伯价值观、能力盘点、矛盾探针，全部经过溯源校验，且配了自动校验脚本——改题库必须跑校验，防止"顺手改题"破坏测量一致性。报告里的市场与政策数据必须过核查清单，媒体数据一律标注"待核实"。

**隐私是架构问题，不是态度问题。** 仓库做公开层/私密层物理分层：方法资产（题库、SOP、模板）去个人化后可公开；原始语料、咨询记录、个人生涯档案物理隔离在私密层，远程仓库的 private 属性是明确设定的防线，写进项目宪法。

## 具体实现步骤

**1. 从真实使用提炼流程。** 阶段一不是"设计"出来的，是把在 dsh 里真实执行过的一整套自我探索流程做知识提纯：哪些提问真挖出了东西、哪些环节需要外部数据校准、报告什么结构真能指导行动。

**2. 题库工程化。** 六个题库落为 JSON，去个人化，写校验脚本把"题目与维度映射、选项完整性"变成 CI 式检查；模板与 SOP 同步版本化。

**3. 封装成 Claude Skill。** 完整执行编排封装为 career-atlas Skill：触发场景（职业探索、迷茫期方向收敛、考研就业决策）→ 收集输入 → 分批施测 → 矛盾挖掘 → 外部校准 → 按模板出报告。资产与 Skill 相对路径打包，拷贝即分发。

**4. 阶段二：Web 应用（CareerAtlasApp）。** Next.js 15 + Tailwind + better-sqlite3，题库用同步脚本从资产库单向同步（资产库是唯一事实源）；LLM 走火山方舟 OpenAI 兼容端点。两个实战坑值得记录：

- **reasoning 模型会吃光 token 预算**：报告生成 max_tokens 必须给到 16384——8192 会被推理链截断在后半节，且提示词要硬要求"六节必须全输出"；
- **降级路径要有测试**：`pnpm e2e:no-llm` 跑 7 项降级用例，保证没配 API Key 时应用依然可用可演示。

## 参考了什么思想

- **心理测量学**：大五人格（Big Five）、霍兰德 RIASEC 职业兴趣模型、舒伯（Donald Super）价值观量表——经典工具负责"问得准"，溯源校验负责"不被改坏"。
- **苏格拉底式追问**：矛盾探针专门挖答案之间的自相矛盾——"你说稳定最重要，却给高风险选项打了最高分"，分歧处才是自我认知的入口。
- **循证咨询**：一切外部断言必须核实后引用，媒体数据默认"待核实"——把循证医学的态度搬进生涯咨询。
- **隐私工程 / 数据最小化**：公开层与私密层物理分层，去个人化是分发前提。
- **单一事实源**：App 不维护题库副本，永远从资产库同步——和 AnimaEVA 篇的"锁文件复现"是同一个工程信条。

## 现状与待补

阶段一完成（资产库 15 个提交，私有备份）；阶段二应用已完成并开源（[careeratlas-app](https://github.com/RUI-debug769/careeratlas-app)，MIT，20 单测 + 完整 e2e）。待补：部署给熟人试用、年度复测机制、行动清单周更追踪。

**声明**：本项目不是心理测量工具，不构成任何心理诊断或临床结论，仅用于自我认知与职业探索。
