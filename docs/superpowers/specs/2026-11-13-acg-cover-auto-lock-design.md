# 自动分配与自动锁定补充设计

日期：2026-11-13

## 目标

新文章创建或运行 `covers:assign` 时，无需手动设置 `image`，也无需执行 `covers:lock`。系统自动分配、扩充、校验并锁定封面；锁定后保持稳定。

## 已确认策略变更

- 取消逐批人工目检，不再以 `covers:lock` 作为常规发布步骤。
- 未使用的已审核图库图片直接自动分配并锁定。
- 库存不足 4 张时，自动扩充 8 张候选；只有全部通过技术检查的候选才可自动入库。
- 自动锁定失败、重复分配、来源不完整、尺寸不足、重复图片或写入恢复失败时，构建必须停止，不发布半成品。
- 用户之后仍可手动覆盖封面，但不能用手动图片绕过未分配错误。
- 当前 `2026-11-07-diting-write` 已锁定的 Neuro-sama 不变，不重新分配。

## 工作流

1. 新文章命令调用分配入口，读取文章主题并选择未使用图片。
2. 库存不足时调用扩充，下载仅来自 Safebooru 白名单主机及 X/Twitter 原作页、rating 为 general/safe 的候选。
3. 每张图片必须通过真实格式、有效方向尺寸至少 1600×900、来源作者、SHA-256 去重和 fit 处理。
4. 复用现有事务日志、互斥锁和崩溃恢复机制，自动完成图库、映射、图片和 frontmatter 更新。
5. 成功后返回 `{postId, coverId, image}`；失败时保持原状态并给出可操作的错误。
6. 构建只读验证唯一分配和正式资源，不联网、不修改文章。

## 审核与错误边界

- 逐批人工审核取消后，来源与内容安全依赖明确的站点、标签、作者、文件和尺寸规则，不声称进行了人工视觉审核。
- 授权备注仍只记录真实来源，不把可下载写成已获许可；用户可在构建或上线后替换不合适的图片。
- 自动扩充不足 8 张合规图片时整批失败，不降低标准。
- 自动锁定与重复执行必须幂等，不能重复追加图库条目或重复映射。

## 验证

- 新文章创建后无需人工 `covers:lock` 即可得到唯一图片并通过构建。
- 库存足够和库存不足两条路径都验证自动锁定、幂等、失败回滚及 pending 不残留。
- 现有 11 篇文章映射不变，当前谛听仍为 Neuro-sama。
- 定向 Node 测试、生产构建和 Playwright 验证；仓库既有失败单独记录。
