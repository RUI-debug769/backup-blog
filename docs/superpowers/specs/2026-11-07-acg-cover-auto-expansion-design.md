# ACG 封面自动扩充与唯一分配设计

日期：2026-11-07

## 目标

让新博文自动获得未使用的高清 ACG 封面。图库不足时生成候选包，经用户目检确认后才锁定。锁定后的文章与图片关系必须稳定，刷新、重建和部署不再变化。

## 已确认决策

- 采用“写文章时分配，构建前校验”。
- 新文章在分配时一律覆盖已有 `image`，但这是分配阶段的一次性覆盖，不是每次构建都重新随机选择。旧文章的既有映射不批量改写。
- 候选图片由用户目检后锁定；未审核图片不能进入正式图库或线上页面。
- 优先使用图库中尚未分配且已经审核的图片；可用库存不足 4 张时生成 8 张新候选。
- 所有原图至少 1600×900，禁止低清放大；候选和正式图片只使用全年龄、来源可追溯的日系二维作品。
- 正常构建及读者浏览器不请求 ACG 网站。下载只发生在本地扩充命令中。

## 方案边界

采用本地分配脚本、候选包和显式锁定，不采用构建时联网直接发布，也不新增 GitHub Actions 定时任务。

### 分配命令

提供三个本地命令：

- `covers:assign --post <id>`：为一篇尚未分配的文章生成待审核分配；新文章命令也调用同一入口。
- `covers:expand`：当未分配图片不足 4 张时生成 8 张候选及联系表；库存足够时不下载。
- `covers:lock --batch <id>`：用户确认某个批次后，把候选写入正式图库、文章映射和 frontmatter。该命令本身就是批准动作，不自动提交或推送。

候选批次写入被 Git 忽略的 `.shirones/cover-expansion/<batchId>/`，包含原图、来源清单、尺寸与格式检查、SHA-256、文章分配建议和联系表。候选文件不能进入 `dist` 或公开页面。

## 唯一分配与锁定规则

1. 正式图库继续以稳定 ID 标识每张图片，`postCoverAssignments` 记录文章 ID 到图库 ID 的一对一映射。
2. 新分配先计算所有已锁定映射和已锁定 frontmatter 中的使用记录，排除已经使用的图库 ID、来源作品 ID 和文件 SHA-256。
3. 候选按文章标题、分类、标签与图库主题的匹配度排序；同分时使用文章 ID 的稳定哈希作为可复现的次序，不使用当前时间或随机数。
4. 只有用户执行 `covers:lock --batch <id>` 后，才追加新图库条目、写入 `postCoverAssignments[postId]`，并把该文章的 `image` 覆盖为 `../../assets/images/post-covers/<file>.webp`。
5. 锁定操作必须可重复执行：同一批次第二次执行不得追加重复图库条目或重复映射。锁定时重新检查冲突，发现其他进程已占用图片则拒绝，而不是覆盖另一篇文章。
6. 锁定先在内存中构造完整的新图库、映射和 frontmatter，并写入临时文件；全部校验通过后才原子替换正式文件。任一步失败都恢复锁定前备份，不得留下部分文章已覆盖、部分图库未写入的不一致状态。
7. 新文章分配完成后不再使用哈希回退。任何未分配文章都会被构建闸门拦截，不能用手动 `image` 绕过。已有正式映射的文章仍保留原有手动覆盖行为。

## 扩充候选要求

- 只从可核实作品信息的 ACG 图片站或原作者作品页获取候选，优先 Safebooru 的全年龄结果、Danbooru 的 `rating:g` 结果和可访问的 Pixiv 原作页。
- 每项必须有 HTTPS 原作品页、作者、来源网站、主题标签、授权备注和替代文本；无法确认来源的候选直接淘汰。
- 图片必须经过真实文件格式与 Sharp 尺寸检查，有效方向尺寸至少 1600×900。
- 来源作品 ID 与文件 SHA-256 用于排除已存在图片；联系表供用户排除画风、构图或近似内容上的重复。
- 授权备注必须如实区分“可下载”和“获得许可”，不得虚构授权。公开部署仍需用户确认使用范围。

## 构建闸门

在文章数据装配前增加全量唯一性校验：

- 当前每篇公开文章都必须有一个正式分配；缺失时提示对应 `covers:assign --post <id>`。
- 不同文章不能共用同一个图库 ID；发现重复立即失败并列出文章 ID。
- 存在未锁定候选批次时，构建提示先审核或移除批次，不能静默发布。
- 图库文件缺失、类型错误、来源字段不完整或尺寸不达标均使构建失败。

正常 `dev` 与 `build` 不执行联网扩充，不修改图库或文章 frontmatter。

## 当前文章迁移

对 `2026-11-07-diting-write` 单独运行分配流程。它当前的手动产品截图 `/images/diting/main-light.png` 只在审核锁定时被新封面替换，正文中的截图保持不变。候选从现有 6 张未分配且已审核的图片中选择，不为了这篇单独联网下载；审核前不修改线上内容。

旧的 10 篇显式映射保持不变。新机制只处理其后新增或尚未分配的文章。

## 错误处理与并发

- 候选下载失败、来源失效、文件不是图片、分辨率不足或重复时，该候选失败，不用低质图片补齐数量。
- 锁定采用单批次写入与冲突复查，禁止两个进程同时分配同一图片。
- 锁定失败时保留候选和来源清单以便排查；不得留下部分文章已覆盖、部分图库未写入的不一致状态。
- 不自动提交、不自动合并、不自动部署。后续提交仍需用户确认。

## 验证与成功标准

1. 单元测试覆盖库存优先级、主题排序、唯一性、重复来源/哈希拒绝、4 张阈值、8 张扩充、幂等锁定和并发冲突。
2. 构建测试证明未分配文章、重复分配和未审核批次都会失败，且构建无网络请求。
3. 当前谛听文章经审核锁定后得到一张不重复的高清封面，旧 10 篇映射与正文均不变。
4. 重新执行分配、锁定和构建，文章封面保持一致；其他文章不能分配到同一图库 ID。
5. 首页、规范详情页和旧重定向继续显示本地响应式图片，浏览器不请求 ACG 网站。
6. 完整验证包括定向 Node 测试、封面 Playwright、生产构建和实际线上检查；仓库既有失败单独记录，不能声称全仓全绿。
